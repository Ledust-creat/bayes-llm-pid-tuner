# 串口协议与试验契约

协议层只处理通用目标与反馈；实际控制环、参数单位和停止行为由下位机决定。当前配套STM32使用USART2、115200、8N1、ASCII、逗号分隔、CRLF结尾，无CRC、序号或NACK。单行最多128字节（含行尾）。

| 上位机命令 | 成功应答 | 说明 |
|---|---|---|
| `PING` | `OK` | 只检查通信，不保证可启动 |
| `SET_PID,kp,ki,kd` | `OK` | 仅允许状态下应用；本机JSON与固件的参数范围必须一致 |
| `RUN_STEP,target,duration_ms` | `OK`，随后`DATA` | 启动一段有时限试验；固件到时停止，不另发完成消息 |
| `STOP` | `OK` | 固件关闭控制与PWM；不保证机械已静止或已经制动 |

所有命令与响应都以`\r\n`结尾。遥测格式为`DATA,elapsed_ms,target,feedback\r\n`，时间为非负整数毫秒，目标和反馈必须为有限数值。下列仅为格式示例，不是测量证据：

```text
OK
DATA,10,20.000,1.238
DATA,20,20.000,2.417
```

被拒绝或格式错误的命令可能被固件静默忽略。上位机一次发一条命令等待`OK`，不自动重发；超时表示未得到确认，不能区分未连接、固件拒绝或其他链路问题。等待期间交错到来的`DATA`会缓存。运行期间只依赖`PING`与`STOP`，不在线修改PID。

## 参数与单位

| 契约 | 谁决定 | 上位机设置 |
|---|---|---|
| 当前控制环、Kd是否可用 | 固件应用 | `experiment_name`、`pid_id`只是描述，不切换固件 |
| PID允许范围 | 固件及人工确认 | `ranges`约束主机搜索与发送，不修改固件 |
| 目标范围和时长上限 | 固件 | `protocol_limits`及端点包含规则 |
| 目标与反馈单位 | 双方应用约定 | `feedback_unit`只显示，不自动换算 |
| 评分坐标 | 实际控制的坐标定义 | `response.cyclic_period=0`为直接相减；非零为周期最短差 |

当前绝对位置固件传输度数，目标范围`[-360,360)`、示例最长5000ms；逻辑位置连续累计，误差直接相减，因此周期设0。350°到−350°是−700°位移，不是20°。反馈不因目标范围而自动折返或钳位。

## 一次试验与停止

主机握手、人工确认后，发送本轮PID，再发送目标和时长，收集遥测；每次结束请求`STOP`并确认后才进入下一次。多目标时同一组参数依次运行列表内全部目标，任一目标无效则中止，不用其他目标的平均分掩盖失败。

正目标速度可启用持续负向/近零反馈异常判定；位置坐标允许负值与零位，应关闭此判定。绝对反馈截止、时间/目标校验、通信超时和STOP确认仍保留。主机保护依赖遥测，不能替代固件保护、限流电源与断电手段。

该协议没有回零、起点复位、固件版本或当前PID回读命令。首帧是指令后的起点估计，复测前由操作者维持一致起点；固件升级或单位、工况改变时建立新历史。
