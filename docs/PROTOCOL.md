# 串口协议与试验契约

协议传递通用的 PID 参数、目标值与反馈值，不携带被控对象名称或物理单位。设备负责本地控制，上位机负责执行试验、记录和优化；位置角度、转速等由具体应用解释。

默认串口配置为115200、8N1，文本使用ASCII、逗号分隔、CRLF结尾，无CRC、序号或NACK；本实现单行最多128字节（含行尾）。串口号和波特率可在GUI设置，设备端需采用一致的通信格式。

| 上位机命令 | 成功应答 | 设备端约定 |
|---|---|---|
| `PING` | `OK` | 检查通信；不代表已满足试验启动条件 |
| `SET_PID,kp,ki,kd` | `OK` | 在允许设置的状态应用参数；只对已接受的命令应答 |
| `RUN_STEP,target,duration_ms` | `OK`，随后`DATA` | 执行有时限的目标试验，到时结束；不另发完成消息 |
| `STOP` | `OK` | 结束控制输出；具体停止方式由设备实现 |

所有命令与响应都以`\r\n`结尾。遥测为`DATA,elapsed_ms,target,feedback\r\n`，时间是非负整数毫秒，目标和反馈必须为有限数值。下列仅演示格式，不指定单位：

```text
OK
DATA,10,20.000,1.238
DATA,20,20.000,2.417
```

被拒绝或格式错误的命令可能被静默忽略。上位机一次发一条命令并等待`OK`，不自动重发；超时表示未得到确认，不能直接断定是端口未连接还是设备拒绝。等待期间交错到来的`DATA`会缓存。运行期间只依赖`PING`与`STOP`，不在线修改PID。

## GUI配置与设备能力的对应关系

| 项目 | 设备端职责 | GUI设置的作用 |
|---|---|---|
| 控制对象和PID算法 | 实现实际控制方式、决定是否支持I/D | 对象名称和PID历史名称用于标记；P/PI/PD/PID选择主机搜索哪些参数 |
| 增益允许范围 | 接受有效参数，拒绝不允许的值 | `ranges`约束搜索与发送，不改变设备允许范围 |
| 目标及试验时长 | 按应用校验目标、单位和最长时长 | `protocol_limits`及端点规则用于发送前校验 |
| 目标和反馈单位 | 按双方约定收发一致的单位 | `feedback_unit`用于显示，不自动换算 |
| 评分坐标 | 提供符合实际定义的反馈 | 周期0按直接差评价，非零按周期最短差评价；不修改设备算法 |

例如位置角度应用可约定用度数收发，而转速应用可约定用rad/s；两者的数据行结构相同。若位置采用绝对坐标，350°到−350°的位移是−700°，评分周期应设0；若控制的是周期方向角，才按相应周期最短差评价。设备允许目标在±360°内，不等于反馈必须按720°折返。

## 一次试验与停止

握手并人工确认后，上位机发送本轮PID，再发送目标和时长、收集遥测；每次结束请求`STOP`并确认后才进入下一次。多目标时，同一组参数依次运行全部目标，任一目标无效则中止。

持续负向/近零反馈判定只适用于这些现象确实代表异常的试验，例如要求持续正向跟踪的场景；合法反馈可以为负或零时应关闭。绝对反馈截止、遥测时间/目标校验、通信超时和STOP确认仍保留。上位机检查依赖串口，不能替代设备本地保护与紧急停止措施。

STOP成功表示设备确认处理了停止命令，不保证物理过程立即停止，例如电机可能惯性滑行、加热对象可能有余热。当前协议没有起点复位、设备版本或当前PID回读命令；操作者需安排可比较的起点和条件，设备程序、单位或工况改变后应建立新历史。

已验证的应用示例是STM32电机控制，使用USART2；这属于示例设备的端口选择，并非其他设备必须使用USART2。适配入口见 [GUI操作与应用示例](motor_bo_gui.md)。
