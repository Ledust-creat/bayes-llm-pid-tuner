# PID自动整定桌面界面

这是本机运行的 Python / Tkinter 桌面窗口，复用现有实机入口、串口协议和评分。
可填写被控对象名称与反馈单位；下位机负责决定实际控制哪个环路，界面中的名称不会切换固件。
无需 Qt、浏览器、网页前后端或新增 pip 依赖。Python 安装需要包含 Tcl/Tk；标准 Windows 安装通常自带。

## 启动

在项目目录双击 `start_motor_gui.bat`，或运行：

```powershell
.\venv\Scripts\python.exe motor_bo_gui.py
```

首次使用者按根README建立虚拟环境并安装`requirements-motor-bo.txt`，然后直接打开GUI。
缺少本机设置时，软件自动从公开模板生成默认配置；已有设置不覆盖。启动不打开串口、不请求API，
不需要先跑仿真或手动复制JSON。实机参数在“运行配置”“边界与时序”中填写，API在“API”页填写并单独保存。

窗口右上“主题”可切换浅色、深色、浅绿背景；面板、日志、表格、输入框及曲线背景同步更新。
选择自动保存在 `motor_bo_gui_settings.json`，下次启动恢复。主题不会修改电机配置或API配置，运行中也可切换。

## 配置与操作

| 位置 | 内容 | 怎么保存 |
|---|---|---|
| 运行配置 | COM口、对象/单位、目标、时长、模式、历史、轮数、Kp/Ki/Kd及边界 | 顶部“保存配置” |
| 边界与时序 | 目标上下界/端点、时长上限、评分坐标/容差、异常判定、超时与随机初始化 | 顶部“保存配置” |
| API | provider、base_url、model、密钥 | API页“保存API配置” |
| 运行记录 | 逐轮评分、全量CSV曲线、中文AI评价及已有SVG | 软件自动保存，点击“打开记录目录”查看 |

首次先在“运行配置”顶部点击串口旁的“刷新”，选择实际COM口并核对波特率。
README预留了串口、运行参数和API页截图位置，截图中的API密钥必须保持隐藏。

修改后点击“保存配置”。保存时先检查字段与原有规则，错误会显示在对话框中，原JSON不被覆盖。
`_注释`和界面未展示的字段仍保留。如果外部编辑器修改了文件，界面要求重新加载，避免覆盖他人的修改。
API配置单独点击“保存API配置”；密钥默认遮挡且不写入运行日志。
原有 `MOTOR_BO_*` 环境变量优先级仍高于 API 文件。

点击“连接并准备”会保存实机配置、启动后台进程并执行 PING。收到 OK 后，“确认开始”按钮亮起；
点击它才向后台输入 START 并开始电机试验。界面中不用手敲 START。

左栏滚轮采用45像素步幅及短动画，鼠标在标签、输入框和下拉框上都可以滚动；
滚轮不会误改下拉框选项。也可以直接拖动右侧滚动条。

## PID参数与多目标

| 设置 | 行为 |
|---|---|
| 搜索参数：PI调参（D固定） | pid_mode=pi；搜索Kp/Ki，Kd使用baseline.kd；默认0 |
| 搜索参数：PD调参（I=0） | pid_mode=pd；搜索Kp/Kd，Ki严格固定0；固定复测也发送Ki=0 |
| 搜索参数：P调参 | pid_mode=p；只搜索Kp，Ki/Kd固定0 |
| 搜索参数：PID调参 | pid_mode=pid；搜索三维范围，记录并发送实际Kd |
| 固定复测 | 发送fixed_repeat中的Kp/Ki/Kd，PD仍固定Ki=0；不搜索、不调用AI |
| 目标列表：15.5,25.5,65 | 每组PID依次测试这三个固定条件，各次时长使用同一配置；每次结束都STOP |

Kp/Ki/Kd像普通参数一样填写，均检查有限值、非负及配置边界。上位机不再以“D能力”开关禁止非零D；
由下位机决定是否接受。当前仅支持PI的固件可能静默忽略非零D，表现为等待OK超时，不能误以为D已经生效。
目标列表为1～10个不重复目标，不是优化变量；正、负、零及端点是否允许由协议范围配置决定。
每组PID的综合分=(1-w)×各目标评分均值+w×最差目标评分，w默认0.3；单目标评分保持原样。
每目标独立保存CSV和评分；任何目标无效都会停止剩余试验，不用平均分掩盖失败。
例如20轮、3个目标会实际执行60次阶跃；时长按每目标计算。
改变搜索维度、固定D、目标列表/顺序、综合权重、时长或单位需要新建历史，避免混用不同条件的结果。
AI仍只调整探索倾向及搜索范围；P建议只包含kp；PD建议只包含kp/kd，不能加入Ki；PID建议包含kp/ki/kd。
P模式下I/D输入及边界变灰，PD模式下I变灰；切换回其他模式恢复未保存的固定输入。
选择PD并不替下位机实现D算法；非零D不受支持时仍可能静默忽略并超时。
旧tune_d配置及历史继续兼容，新配置统一使用pid_mode；不同模式的历史不可混用。

“停止”通过标准输入通知后台；串口操作仍由唯一后台线程完成。
若试验正在采集，后台跳出采集并发送 STOP，保存已收到的部分遥测；不再启动后续轮次。
界面关闭时先请求停止，等后台退出后关闭窗口，不强杀进程。
串口命令等待受原有超时约束；AI请求阶段电机已停止，关闭窗口可能等待该次请求超时。
日志只有收到固件 OK 才显示“停止命令已确认”，STOP超时仍会报告异常。

## 看曲线与复测

右上运行列表包含实机调参和固定复测。选择历史运行可查看所有轮次曲线；轮次颜色与评分表一致，
点击表格第一列勾选/取消显示；支持全部显示、全部隐藏、仅显示最优组，不再点击加粗。
筛选按钮固定在曲线上方，评分表在曲线下方；窗口缩小时优先保留筛选与表格，图表自适应剩余高度。
多目标时一轮对应多条曲线，轮次同色，目标值在表格中区分；表格显示该目标的独立评分，顶部最佳分是综合分。
运行期间按终端采样频率显示当前目标预览，轮结束后读取完整CSV。
隐藏仅影响当前窗口，不删除数据；SVG仍包含全部轮次与目标。
“打开SVG曲线”可查看原有矢量图，“打开记录目录”可直接查看原始数据。

“所选记录最优 → 复测”从所选运行的有效轮次中取最低综合分，将 Kp/Ki/Kd、目标、单位和时长填入界面，
并切换为固定复测；重复次数使用当前配置。原协议和评分条件也会导入，然后保存或连接即可复测。
当前对象的评分类型或单位与历史不同，会拒绝导入，防止将速度最优误当位置最优。
它不会自动扩大硬边界；若历史参数不在当前边界内，需要用户核对当前固件后修改边界。
左侧“固定参数复测”里的“当前PID历史最优 → 复测”不依赖右侧选了哪张图：按PID历史名称读取
当前active系列中所有已完成批次的综合最优，并导入原目标列表、时长、模式及评分权重。
它不合并已被new重置的旧系列，不读取未完成批次；没有完成历史时可用所选记录导入。
两个按钮均只填入界面，不自动保存、不自动通电；次数、串口与人工硬边界保持当前设置。

选择状态为“AI暂停”的记录，点击“恢复所选暂停”，会使用暂停时保存的试验配置；
串口设置仍读取当前实机JSON，握手后再点击“确认开始”。普通停止、失败和完成的记录不能恢复。

GUI终端输出实时保存到 `motor_bo_terminal_latest.log`，每次新任务覆盖；CSV与历史记录仍各自独立保留。
“实时日志”页顶部的“清空日志”只清空窗口显示，不删除日志文件、CSV或历史记录，也不停止试验。
运行期间可以清空，后续新消息仍正常显示，AI评价不受影响。
以后可以直接让 agent “读最新终端日志”或“分析最新一次调参”。

## 范围

这一版界面管理实机配置及共享API配置。原仿真入口与 `motor_bo_config.json` 继续按原方式使用。
已支持固定多目标综合评分、带符号目标和位置坐标；DATA仍为通用target/feedback，不自动换算单位。
“反馈异常判定”中的负向/近零判定仅适用于正目标跟踪。位置坐标可合法为负或停在零位，应关闭该开关；
绝对反馈截止、遥测时间/目标校验、超时及STOP确认检查仍有效。主机检查不能替代下位机保护。
首批随机参数组用于探索增益组合，不是采样点；随机种子用来复现候选序列，不是转子，不能保证实机测量重复。
新配置用target_values、feedback_abs_limit及protocol_limits.target_min/target_max；旧rad_s字段仍兼容读取，
新CSV表头为elapsed_ms,target,feedback。旧SVG文件名speed_response.svg保留，但坐标按实际单位显示。

## 位置环配置与评分

当前STM32位置固件的命令目标和反馈都用“度”，允许目标[-360,360)，最长5000ms；不是机械速度rad/s，也不由pid_id切换环路。
左侧“边界与时序”中将协议下限设-360、包含下限，上限360、不包含上限，时长上限5000；“评分与坐标”选择位置阶跃。
当前固件逻辑位置连续累计，误差直接相减，因此cyclic_period设0。目标允许范围±360度不是720度周期，
也不限制连续反馈只能在该区间；只有实际采用周期最短差的控制对象才配置非零周期。

| 配置 | 作用 | 位置环示例 |
|---|---|---|
| response.initial_reference | 阶跃起点取固定值或首帧估计 | first_sample |
| normalization_floor | 归一化除数的下限，零目标也能评分 | 1度 |
| settling_tolerance_abs / ratio | 稳态误差带取两者较大值 | max(1度,阶跃幅度×5%) |
| cyclic_period | 0为直接相减；非零才使用周期最短差 | 0 |
| trial_guard.enabled | 正目标跟踪的负向/近零检查 | false |

单目标分数越低越好，仍为70%归一化绝对误差+20%沿阶跃方向的超调+10%稳定时间比例。分母用max(阶跃幅度,归一化下限)，
因此零目标不会除零，负目标不会得到负误差分数；当前绝对坐标中350度到-350度是-700度位移，不折返成20度。
首帧约在命令后10ms，起点只是估计；记录会保存initial_reference、initial_feedback、step_amplitude和hold_only。
若一开始已经在目标处，这是保持位置测试，不是完整阶跃响应，不能用它证明阶跃调参成功。
协议没有回零/起点重置命令，因此位置复测需要确保起点一致；否则同一PID可能因位移不同得到不可直接比较的分数。
改变单位、评分口径、起点规则、容差、周期或异常判定后必须history_mode=new，不混用速度历史。
旧720度周期评分的记录按原配置保留，不与修正后的绝对位置评分合并。在GUI中选择位置阶跃、填写度数、
相应协议范围和周期0，关闭负向/近零判定并填写可运行基线即可；不需要通过切换JSON文件来配置位置模式。
发布包中的位置示例只是结构参考，P默认0；实际参数仍应在界面核对。
适配其他设备仍需核对固件、增益单位、停止条件和测试时长，界面不会自动实现设备控制算法。
